## 2. 三条路线对照（数字全部来自 09-22 那份只读推算）

| | **B 保留原分辨率** | **C 换 BC7** | **D 换 BGRA8 无压缩** |
|---|---|---|---|
| 要改什么 | 整块重建 `.uexp`（`SizeX@2/SizeY@6/DataSize@50/SizeX@74/SizeY@78/MipCount@102` + 全部 mip 负载 + 尾部 mips-in-tail 表）+ uasset 的 `SerialSize` | 同 B，再把格式串 `PF_DXT1`→`PF_BC7`（**uasset 名字表要加 `PF_BC7`**），块尺寸 8→16 B | 同 B，格式改 `PF_B8G8R8A8`，像素按行直写 |
| 单张贴图体积（含完整 mip 链） | 1440p **2.46 MB** / 4K **5.53 MB** | 1440p **4.92 MB** / 4K **11.06 MB** | 1440p **19.66 MB** / 4K **44.24 MB** |
| 两张 + DA 的容器量级 | 4K ≈ **11 MB** | 4K ≈ **22 MB** | 4K ≈ **88 MB**（1080p 也有 22 MB） |
| 画质预期 | 消失的是**降采样损失**（源图本来就 2560×1440 ⇒ 等于不再降）；BC1 量化本身不变 ⇒ PSNR 与现在同级（≈35–41 dB）但**高频细节回来** | 渐变区**色带明显减少**（BC1 每块 2 端点 + 565 量化 vs BC7 8 模式高精度端点）——二次元大图最刺眼的就是色带 | **无损**（PSNR = ∞）；代价是运行时显存/带宽上升（4K ≈ 33 MB/张） |
| 依赖 | 无（我现有链路就能做） | **必须有 BC7 编码器**：装 Compressonator/texconv（需你同意联网+安装）**或你给 `.DDS`（我写 ~40 行 DDS 解析器，BC1/BC3/BC7 通吃）** | 无（不需要任何编码器） |
| 风险 | 中：首次"整块重建 uexp"，必须走 **离线重建 → CUE4Parse 断言 → 分阶段真机**；`retoc` 对尺寸/格式无感知（只按包与块工作），引擎侧已证 4096 宽 DXT1 能跑（游戏自带缩略图图集就是 4096×2048 DXT1） | 同 B 级；多一项"编码器来源"决策；sRGB 标志要保持对（渐变按 sRGB 采样才不发灰） | 同 B 级；只需保证 sRGB 与尺寸字段一致 |
| 离线判据（够硬） | `tex-inspect` 断言 `SizeX/SizeY/PixelFormat/NumMipsInTail` 与每级 mip 的 `sha256` | 同上 + `PixelFormat="PF_BC7"`、mip 链按 BC7 规则 | 同上 + `PixelFormat="PF_B8G8R8A8"` |

## 3. **新增事实（09-22 那份没有、但会影响选型）**

1. **`MI_<名字>` 的 6 个标量是写死 1920×1080 的**：`SpriteX/Y=0`、`SpriteWidth/Height=1920/1080`、`TextureWidth/Height=1920/1080`。
   ⇒ 只要走 B/C/D 改了贴图尺寸，**这些标量必须一起改**，否则预览材质取景/精灵区算错（现在缩略图能正常显示，靠的就是这 6 个值与 1920×1080 贴图一致）。
   ⇒ 实现上很小（`core/config.py::MI_SCALARS` 改成按实际尺寸生成），但**属于必须记得改的一环**。
2. **宽高比策略已经放开了"只能 16:9"**（v1.1.0，你的原话："按宽高比判定，而不是严格卡死 16:9…引擎自带的拉伸我们可以接受"）：
   ⇒ 路线 B 用 **2560×1440** 完全符合现行门（宽>高即放行，非 16:9 只警告）；`-Fit contain` 那条路会把图补成 1920×1080，**与 B 互斥**（走 B 就不该 contain）。
3. **A0 的 MI 壳 roundtrip 判据（A8 缩略图通道）已经存在**，所以 B/C/D 改完不会"没人盯画质"：
   `A8`＋`QUALITY: PSNR/MAE/清晰度比` 会一起把"缩略图仍是我们的图、且画质达标"钉住。
4. **外部依赖现状**：本机 PATH / 项目 `tools\` / `C:\Program Files` 下**确实没有** `texconv`、`CompressonatorCLI`、
   `nvcompress/nvtt`、`astcenc`、`basisu`；Python 侧也没有 BC 编码库。⇒ 走 C 就必须先解决"编码器从哪来"。
